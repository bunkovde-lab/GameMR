## Наборы сценариев

**Сценарий A — наблюдение.** Дефолтный слой «События»; пять вызовов без группировки, правая панель закрыта; открыть/закрыть список. Открыть район с клавиатуры, затем вернуть обзор.

**Сценарий B — тревожный вызов.** Выбрать `medriot`, увидеть правую карточку, проверить ETA и требования к назначению, отправить «Аксон», включить слой патрулей и наблюдать движение на ×1/×2.

**Сценарий C — дорожный сбой.** На середине маршрута закрыть ребро; ожидается reroute или честный «Нет пути»; перезагрузить и проверить состояние.

**Сценарий D — планшет.** Развернуть экран на 1194×834, скрыть левую колонку и открыть правую карточку, проверить кнопку отправки и минимум 44×44 CSS px интерактивную площадь.

**Сценарий E — маленький экран.** 844×390; выдвижные панели не перекрывают одновременно весь экран, у каждой есть закрытие, выбранное событие восстанавливается после закрытия.

## Инженерные пороги

- Marker-vs-landmark screen drift: **до 3 CSS px** после последовательного zoom/pan/resize (без учета искусственного сдвига при кластеризации).
- Для кнопок и маркеров интерактивная цель: **не меньше 44×44 CSS px**.
- Рекомендованный размер интерактивного текста: **14+ CSS px**, основные действия **16+ CSS px** на планшете.
- Никакого одновременного появления «пауза» и движущегося ETA из независимых таймеров.
- Целевое быстродействие ≥30fps на целевом планшете при 20 событиях/6 отрядах; фактические результаты приложить отдельно.

### Передача пользователю

Work обязан предоставить скриншоты, минимальную воспроизводимую сборку, инструкцию запуска, журнал тестов PASS/FAIL и перечень ограничений. Если что-то из P0 не работает — этап **не принят**, даже если картинка красивая.
