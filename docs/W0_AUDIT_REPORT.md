## 1. Итог в пяти пунктах

1. **В репозитории GitHub игрового кода нет.** Есть только документация: ТЗ v2.0, W3, CLAUDE.md, художественный регламент, каталог ассетов и пустой `assets/manifest.json`.
2. **Архив `GameMR_W0_CORE_Map_Prototype.zip` читается полностью.** В нём есть утверждённая карта, `map_config.json`, демо-данные W3, реестры экранов, матрица приёмки, ТЗ v1.0 и старый прототип в двух вариантах: исходники и standalone-файл.
3. **Карта прошла проверку.** SHA-256 файла совпадает с `map_config.json`, размер 1672×941, все центры районов совпадают с ТЗ §4.1 до пикселя, граф из 20 узлов и 24 рёбер связный. Найдены мелкие замечания (§4.4).
4. **Старый прототип работает, но в production его не переносим.** Это демо интерфейса на одном файле JS: состояние смешано с DOM, координаты в процентах, районы от старой карты, сохранения в localStorage без миграций. Переиспользуем **дизайн-токены, компоновку, иконки и тексты**, логику пишем заново.
5. **Решение:** новый каркас **Vite + React + TypeScript** с чистым игровым ядром, как требует ТЗ §1.2 и §5. План трёх PR в §7.

## 3. Аудит старого прототипа

### 3.1. Как запускался

Файл `legacy/prototype_standalone.html` открывается в Chromium без сервера и без ошибок в консоли. Проверено в headless Chromium (Playwright) на 1920×1080, 1366×768, 1194×834 (планшет) и 844×390 (телефон, горизонтально). Скриншоты лежат в `docs/w0/`.

### 3.2. Что реально работает (проверено автоматически)

- Главный экран по схеме ТЗ §3.1: верхний HUD, список вызовов слева, карта в центре, правая карточка открывается только при выборе, лента отрядов и навигация снизу.
- Выбор вызова, вкладки «Сведения / Риски / Улики», прогноз успеха, риск ранения, ETA, выбор отряда и тактики, разведка, запрос полномочий.
- Отправка отряда: бюджет 105 → 103,75 РЕ, миссия создаётся, состояние пишется в localStorage.
- Пауза и скорости ×1/×2/×4, завершение смены, журнал, слои «События / Патрули / Районы», зум и панорамирование.
- Модальные разделы: Кадры, Расследования, Операции, Развитие, Медицина, Исследования, Досье.
- Горизонтальной прокрутки страницы нет ни на одном размере.

### 3.3. Почему код нельзя переносить как есть

| Проблема | Где | Требование, которое нарушено |
|---|---|---|
| Монолит: 241 длинная строка JS, рендер через `innerHTML`-шаблоны, состояние и DOM смешаны | `app.js` | ТЗ §5.1: чистое ядро `reduce(state, command, rng)`, UI отдельно |
| Координаты районов, событий и отрядов в `%` (`x:56,y:32`) | `districts`, `baseEvents`, `baseSquads` | W3 §1–4: только нормализованные координаты `map_config.json`, без `% left/top` |
| **Районы стоят по старой карте**: «Северные сады» слева сверху, медицинский район в центре | `districts` | W3: сады справа, медицина слева сверху |
| Отряд «телепортируется» к событию (`s.x=e.x`), маршрутов нет | `dispatch()` | W3 §4: Dijkstra по графу, движение по polyline |
| RNG — LCG в общем state, но вызывается из UI-обработчиков; таймер на `setInterval` и wall-clock | `rng()`, `tick()` | ТЗ §5.4: детерминизм, RNG только в ядре |
| Сохранение в localStorage одним ключом, без миграций и слотов | `save()` | ТЗ §5.4: IndexedDB, 3 слота + автослот, миграции |
| Статусы событий `pending/active/done/failed/expired` | `state.events` | W3 §3: `new → acknowledged → … → resolved_*` |
| Формула прогноза не совпадает с ТЗ §6.3 | `forecast()` | формула должна задаваться конфигом |
| 30 из 56 видимых кнопок меньше 44×44 px | все размеры | ТЗ §3.1 и §15.2 |
| На планшете вкладка фильтра «Остальные» обрезана | `.filters` | ТЗ §15.2 |

| Что | Откуда | Как |

### 4.4. Замечания (не блокируют, нужно решение)
1. **Полигоны слегка перекрываются**: admin+medical 0,05 %, admin+science 0,07 %, industry+medical 0,11 % площади карты. Предлагаю при клике в зоне перекрытия выбирать район с ближайшим `labelAnchor`. Это не меняет арт и конфиг.
2. **Полигоны покрывают 64 % карты**, края и море остаются некликабельными. По W3 это допустимо, клик мимо снимает выбор.
3. **`MED_MAIN` — тупиковый узел** (одно ребро). Если в будущем закрыть это ребро, медицинский район станет недостижим. Для W3 это нормально (дороги не закрываются), но к W4 нужен запасной маршрут или правило.
4. **Названия слоёв расходятся**: в конфиге `events, patrols, risks, infrastructure, districts, route-preview`, а в ТЗ §4.4 `events, patrols, routes, districts, threats, infrastructure`. Предлагаю взять ID из конфига, он источник геометрии; нужно подтверждение.
5. Визуально (наложение полигонов и графа на карту) дороги идут по нарисованным магистралям, точки появления стоят на зданиях. Картинку наложения прикладываю к PR в треде, в репозиторий не кладу до решения о приватности.

## 6. Предлагаемая архитектура

**Стек:** TypeScript 5 (strict) · React 18 · Vite 5 · Zustand (тонкий стор поверх ядра) · Vitest (ядро) · Playwright (E2E, touch, скриншоты) · idb-keyval (IndexedDB) · ESLint + Prettier. Без UI-фреймворков: стили через CSS-модули на токенах прототипа.

```text
GameMR/
├─ assets/                      # утверждённые бинарники (карта и т. д.), manifest.json
├─ content/                     # JSON: map_config, incidents, squads, staff, balance_v1_re
├─ src/
│  ├─ core/                     # чистое ядро, без React и DOM
│  │  ├─ state.ts               # GameState, схемы, schemaVersion
│  │  ├─ commands.ts            # PAUSE, SET_SPEED, ASSIGN_SQUAD, DISPATCH_SQUAD…
│  │  ├─ reduce.ts              # reduce(state, command) → {state, events}
│  │  ├─ rng.ts                 # детерминированный PRNG (seed + cursor)
│  │  ├─ time.ts                # игровое время, тики
│  │  ├─ map/graph.ts           # граф дорог, Dijkstra, ETA
│  │  └─ log.ts                 # event log
│  ├─ persistence/              # IndexedDB, слоты, экспорт/импорт, миграции
│  ├─ ui/
│  │  ├─ tokens.css, icons.svg
│  │  ├─ shell/                 # AppShell, TopHud, BottomNav, SquadStrip
│  │  ├─ map/                   # MapView: камера, слои, маркеры, полигоны
│  │  └─ screens/               # экраны добавляются по этапам, не все 22 сразу
│  ├─ store.ts                  # мост ядро ↔ React, единственный вызов reduce
│  └─ main.tsx
├─ tests/
│  ├─ core/                     # unit: детерминизм, инварианты, граф
│  └─ e2e/                      # Playwright: ПК, планшет, телефон, touch
└─ .github/workflows/ci.yml     # lint + typecheck + unit + e2e + build
```

**Ключевые правила (из ТЗ, закрепляются тестами):**
- UI не вызывает RNG и не меняет домен напрямую, только `dispatch(command)`.
- Игровое время двигает единственный цикл `requestAnimationFrame → TICK(n)`; при паузе позиции и ETA заморожены.
- Все координаты на карте: `normalized → mapTransform → screen` в одном модуле (`mapTransform.ts`).
- Одно состояние, один ID: список вызовов, карта и карточка читают одну сущность.

**Браузеры:** последние 2 версии Chrome/Edge, Safari 16+ (iPad), Chrome Android. Firefox желателен, приёмочный gate только на Chromium и WebKit (Playwright).

**Показ на телефоне по ссылке:** сборка — статический сайт. Варианты:
- **GitHub Pages**: бесплатно только для публичного репозитория, то есть зависит от решения о приватности.
- **Cloudflare Pages или Netlify**: бесплатно работают и с приватным репозиторием, дают превью-ссылку на каждый PR. Нужен аккаунт владельца, подключение один раз.

До подключения хостинга проверка идёт локально (`npm run dev -- --host`, телефон в той же Wi-Fi-сети) и по скриншотам Playwright в PR.

- сломанное сохранение не затирает предыдущее;
- инварианты: нет отрицательной кассы без механизма долга, зарплата не списывается дважды;
- кейсы `CORE-*` и `SHIFT-*` из `ACCEPTANCE_MATRIX.csv`, относящиеся к одной смене, в статусе PASS.

- после зума, pan и сворачивания панелей метки не дрейфуют (пиксельная проверка);
- сравнение скриншота: пиксели карты не изменены;
- touch-тест на эмуляции iPad и Android-планшета.

**Дальше (для понимания, без детализации):** W4 диспетчеризация (быстрая/ручная отправка) → W5 исход операции и отчёт → это и есть первый вертикальный срез из CLAUDE.md: вызов → отряд → маршрут → исход → отчёт → сохранение.
