# GameMR — материал для Claude W0 (8 ноября 2026)

Этот ZIP собран из реальных источников v2.0 + старого HTML-прототипа + W3-пакета.

## Где что искать
- `assets/backgrounds/approved_map_original_1672x941.png`: ОРИГИНАЛ утверждённой карты, не перерисовывать, не заменять картой из демо.
- `data/map_config.json`: W3 геометрия районов, точки вызовов, узлы и рёбра дорог; координаты привязаны к утверждённой карте.
- `legacy/prototype_standalone.html`: самостоятельный старый демо-прототип интерфейса.
- `legacy/Mir_Raskola_UI_Project.zip`: исходники того же демо (`index.html`, `app.js`, `styles.css`, placeholder SVG); извлечь перед аудитом. Заглушка карты внутри zip не является утверждённым артом.
- `art_refs/ref_01.webp`—`ref_21.webp`: экранные референсы; названия/цифры на них демонстрационные, а не финальные игровые данные.
- `data/screen_registry.csv`, `data/approved_screen_refs.csv`: реестр экранов.
- `qa/ACCEPTANCE_MATRIX.csv`: критерии приёмки.
- `data/incidents_demo.json`, `data/squads_demo.json`: демонстрационные данные W3, не финальные события кампании.
- `docs/Mir_Raskola_Pravo_na_Poryadok_TZ_v1_0.docx`: историческая модель, часть цифр предварительная.
- `docs/GameMR_Единое_ТЗ_v2_0.md`: актуальное ТЗ.

## Как действовать
1. Сопоставить содержимое с GitHub `bunkovde-lab/GameMR`, где уже есть `CLAUDE.md` и текстовое ТЗ v2.0.
2. Выполнить W0: аудит старого прототипа и всех артов; проверить `map_config.json` на утверждённом PNG.
3. Не считать старый прототип production-ready: выбрать миграцию или новый каркас на основании аудита.
4. Предложить следующее PR для W1 лишь после отчёта W0 и согласования пользователем.
5. После решения о приватности репозитория можно разместить в GitHub источники: карту, конфиг, прототип и референсы отдельными файлами. Не заливать ZIP как единственный источник кода.
