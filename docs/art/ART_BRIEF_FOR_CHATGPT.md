**Версия:** 1.0 · 08.11.2026 · **От:** Claude (ведущий программист) · **Для:** ChatGPT (арт-директор, геймдизайнер)
**Основа:** `docs/ART_STYLE_GUIDE.md`, `docs/ASSET_CATALOG.md`, `docs/UI_ASSET_CONTRACT.md`, ТЗ v2.0 §14.

Владелец разрешил публиковать арты в публичном репозитории и на сайте (08.11.2026).

---

## 1. Главные правила

1. **На картинках нет текста, цифр, кнопок, интерфейса, водяных знаков и подписей.** Весь текст и все кнопки делает код.
2. **Один файл — один объект.** Персонаж отдельно, предмет отдельно, фон отдельно. Никаких «скриншотов экрана» как ассета.
3. **Утверждённую карту не перерисовывать.** Она уже есть (1672×941, SHA-256 `72ef916c…9ddc`).
4. **Единый стиль** во всей серии: в каждом промпте повторять «якорь стиля» из §3.
5. Ассет считается доступным, только когда его файл лежит в репозитории и записан в `assets/manifest.json`.
6. Утверждает вид **владелец** (Дмитрий). Программист проверяет только техническую пригодность.

## 2. Как вести библиотеку

### 2.1. Папки
```
assets/
  backgrounds/   карта и полноформатные фоны без UI
  characters/    портреты сотрудников и персонажей
  locations/     объекты инфраструктуры (8 объектов дирекции и т. п.)
  events/        сцены происшествий и спецопераций
  equipment/     предметы, улики, органы, устройства
  ui/            иконки, маркеры, рамки, эмблемы
  manifest.json  реестр (единственный источник правды о наличии)
art_refs/        утверждённые референсы экранов ref_01…ref_21.webp (только для справки, в игре не используются)
```

### 2.2. Имена файлов
`<категория>_<краткое_имя>_<вариант>.<расширение>`, латиница, нижний регистр, без пробелов.
Примеры: `portrait_p01_mara_kass.png`, `marker_incident_bio.svg`, `event_medriot_approach.webp`.

### 2.3. Запись в `assets/manifest.json`
Каждый файл — одна запись:
```json
{
  "id": "PORTRAIT_P01",
  "file": "assets/characters/portrait_p01_mara_kass.png",
  "category": "characters",
  "role": "Портрет сотрудника p1 (имя временное, OPEN-08)",
  "status": "draft",
  "width": 512, "height": 640, "alpha": false,
  "source": "ChatGPT image, промпт в docs/art/prompts/PORTRAIT_P01.md",
  "approvedBy": null,
  "notes": ""
}
```
**Статусы:** `planned` → `draft` (сгенерирован) → `review` (на оценке у владельца) → `approved` (владелец утвердил) → `integrated` (подключён в игру программистом).
ID не меняются после появления в коде. Новая версия того же ассета — тот же ID, новый файл, старый удаляется в том же PR.

### 2.4. Промпты
Для каждого ассета промпт сохраняется в `docs/art/prompts/<ID>.md`, чтобы через месяц можно было сделать ещё одного персонажа в том же стиле.

### 2.5. Как передавать файлы
- **Вариант А (предпочтительно):** коммит в отдельную ветку `art/<ID или пакет>` и Pull Request в `main`, в описании — список ID и превью. В `main` напрямую не коммитить.
- **Вариант Б:** владелец загружает файлы в тред проекта, программист сам раскладывает их по папкам и заполняет manifest.
- В обоих случаях: исходник лучшего качества (PNG) — в репозиторий, оптимизацию в WebP делает программист.

## 4. Технические требования по типам

| Тип | Формат | Размер | Фон/альфа | Прочее |
|---|---|---|---|---|
| Маркеры и иконки (`ui/`) | **SVG** (предпочтительно) или PNG | сетка 24×24, PNG 256×256 | прозрачный | одноцветные линии, толщина как у текущих иконок (2 px на 24), без цвета — цвет даёт код по уровню угрозы |
| Портреты (`characters/`) | PNG | **512×640** (4:5), лицо в верхней трети | однотонный тёмный фон `#141922`, альфа не нужна | погрудный, взгляд в камеру или на ¾, одинаковый свет у всех; состояния «ранен/погиб» делает код |
| Сцены событий (`events/`) | PNG | **1920×1080** | без альфы | без UI; важное в центральных 60 % кадра (по краям лягут панели) |
| Объекты (`locations/`) | PNG | 1600×900 | без альфы | вид сбоку/сверху в одном ракурсе для всей серии |
| Предметы, улики, органы (`equipment/`) | PNG | 512×512 | **настоящая альфа** | если прозрачность не получается — однотонный фон `#FF00FF` и пометка в PR, программист вырежет |

Проверка перед отправкой: нет текста и цифр; размер и пропорции как в таблице; стиль совпадает с уже утверждёнными; один объект на файл.
